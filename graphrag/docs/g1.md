# G1 — Indexing pipeline

**Status:** code and offline tests complete; live mini run in progress (numbers below
are filled from the artifacts when it finishes).

## What was built

- `corpus.py` I1 — load the corpus directory, deterministic article ids.
- `chunk.py` I2 — paragraph-packed ~1,000-char windows with 150 chars of overlap;
  chunk ids are `article::position` and re-running the chunker is byte-identical.
- `extract.py` I3/I4 — one model call per chunk, JSON salvage, one re-ask for an
  empty/unparseable answer (`GRAPHRAG_EXTRACT_ATTEMPTS`), append-only JSONL
  checkpoint, failed-chunk ledger, and a circuit breaker that stops the run after
  `GRAPHRAG_ENDPOINT_FAILURE_LIMIT` consecutive provider failures instead of
  marking every pending chunk failed.
- `validate.py` I5 — shape, self-loops, vague groups, compound names, name length;
  every rejection is written to `rejections.jsonl` with a reason.
- `normalize.py` I6 — stable entity keys (case, accents, punctuation, leading
  articles, legal suffixes) with the display name kept separately.
- `graph.py` I7/I8 — one edge per (head, relation, tail) with mention counts and
  sorted `source_chunks`, node mention counts, majority type backfill.
- `resolve.py` I9 — token blocking → Jaro-Winkler/token-overlap nomination →
  union-find components → one LLM judge per batch (names, types, mentions, real
  edges) → deterministic canonical rebuild by mention count. Every candidate and
  its verdict is in `merge_log.json`, and `merge_audit.jsonl` holds the same
  verdicts one candidate per line (the I9 audit deliverable); the judge is biased
  to "do not merge".
- `communities.py` I10 — undirected log-weighted graph, deterministic label
  propagation, one summary per community, deterministic fallback summary when the
  model fails.
- `embed.py` I11 — node, fact and chunk vectors with backend/model/dim metadata and
  resumable writes; a cached vector is reused only while the hash of its source text
  matches, so a rebuilt graph never keeps a stale vector under the same key. A
  chat-only endpoint falls back to deterministic hashed n-gram vectors and records
  which backend produced the store.
- `build.py` — stage CLI (`extract|graph|resolve|communities|embed|all`), every
  stage after extraction rebuildable from `triples.jsonl`.
- `graphrag/llm.py` — the package's single model doorway (retries, JSON salvage,
  redaction, usage stats).

## Mini corpus and index

The live run deliberately indexes three articles, so the index and checkpoint
describe the same 40 chunks:

| Item | Value |
|---|---|
| Articles | Alzheimer's disease, asthma, breast cancer |
| Chunks | 40 (15 / 15 / 10) |
| Chunk budget | 1,000 chars, 150 overlap |
| Index characters | 36,344 |
| `index.json` sha256 | `d296e584253827206a3bccc2d46ce082ef077fc862079791c6a08c05fd3cf809` |

## Reproduce

```bash
.venv/bin/python test/data/test_data_fetch.py --pause 2     # full 24-article corpus
.venv/bin/python test/eval/make_mini_corpus.py              # copy the three articles
export GRAPHRAG_CORPUS=test/data/corpus_mini
.venv/bin/python -m graphrag.build --stage extract --limit 40
.venv/bin/python -m graphrag.build --stage graph
.venv/bin/python -m graphrag.build --stage resolve
.venv/bin/python -m graphrag.build --stage communities
.venv/bin/python -m graphrag.build --stage embed
```

`extract` is the only paid stage and is resumable by chunk id; `--retry-failed`
re-bills a failed chunk deliberately.

## Boundary

The graph is a retrieval index over Wikipedia medicine, not a clinical reference.
