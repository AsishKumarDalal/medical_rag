# G3 — Harness integration

**Status:** implemented and covered by an offline round-trip test; a live
transcript is recorded once the G1 index exists.

## What was built

- `graphrag/backend.py` — `GraphRagBackend` is the only harness-facing adapter.
  Importing it is cheap; the index is loaded on the first question, so the CLI
  starts even before the pipeline is built.
- An explicit `_UNSET` sentinel separates "build the default model client" from
  `llm=None` (offline tests). A missing index raises `GraphRagNotReady` and
  becomes a readable tool error.
- `harness/tools/rag.py` — `search_medical_literature` is the real RAG tool.
- `harness/cli.py` — registers `EchoTool` and the RAG tool; `_rag_backend()`
  imports `GraphRagBackend.from_env()` when the package is available.
- The registry caps every tool result at 8,000 characters; larger outputs are
  truncated and H3 can stub them later in the conversation.

## Tool contract

```text
search_medical_literature(question, mode="auto"|"local"|"global", k=1..20)
  -> content: answer + "Citations: article::chunk, …" + "(mode: …)"
  -> data: {citations, evidence_ids, mode, abstained}
  -> error: a readable tool error, never an exception
```

- `question` is required and must be at least 3 characters.
- `mode` defaults to `auto`; `k` defaults to 8.
- Unknown or invalid arguments are rejected by the registry before execution.
- Pipeline exceptions are converted to `ToolResult.error`; they never escape the
  agent loop.

## End-to-end path

```text
user question
  → harness loop sends tool schema to the model
  → model calls search_medical_literature
  → GraphRagBackend.answer
  → query pipeline (G2)
  → cited tool result
  → model writes the final answer
```

The tool result includes stable evidence ids, so the harness can cite the same
chunks the GraphRAG engine used without re-sending full evidence.

## Reproduce

```bash
.venv/bin/python -m harness --once "What is asthma?"
.venv/bin/python -m harness                 # interactive REPL
.venv/bin/python -m pytest -q test/test_graphrag_integration.py test/test_tools.py
```

## Boundaries

- The harness exposes no shell, file, web or Python tools.
- The RAG tool is read-only and returns text plus ids.
- Retrieved text is data, not instructions; the H5 security layer wraps it as
  untrusted evidence.
