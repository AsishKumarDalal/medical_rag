# H4 — Durable sessions

**Status:** complete (`39a9ce6`)

## What was built

- `harness/schema.sql` and `harness/session.py` — SQLite tables for sessions,
  messages, tool calls, context events and usage, created on first use.
- WAL mode, one connection per process, append-only writes while a turn runs.
- Helpers to create a session, append messages, record usage/context events, list
  sessions, load history and resume by id.
- A loop interrupted mid-tool-call keeps every completed step; the next process can
  load the same session.

## Verification

```text
.venv/bin/python -m pytest test/test_session.py -q

```

Tests cover the create → append → reload round-trip, resume after a simulated
mid-loop crash, context-event persistence and isolation between two sessions.

## Boundaries

No users, auth, sharing, migrations or server API. The database holds only harness
state; the corpus and graph artifacts stay on disk as JSON.
