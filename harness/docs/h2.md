# H2 — Tool contract and registry

**Status:** complete (`a154897`)

## What was built

- `harness/tools/base.py` — `Tool` with `name`, `description`, JSON-schema
  `parameters`, and `run(arguments) -> ToolResult`; success/error results carry an
  optional structured payload.
- `harness/tools/registry.py` — name lookup, model-facing `specs()`, contained
  execution (unknown tools, parse errors, bad arguments and tool bugs become error
  results), and an 8,000-character result cap with an explicit truncation marker.
- `harness/tools/validation.py` — recursive JSON-schema checks before a tool runs.
- `harness/tools/rag.py` — `search_medical_literature(question, mode, k)` with the
  final signature and an honest "not wired" stub until G3.

## Verification

```text
.venv/bin/python -m pytest test/test_tools.py -q
13 passed
```

The tests cover discovery, duplicate/nameless tools, every malformed-argument path,
tool exceptions, oversized arguments, result truncation, and the RAG stub.

## Boundaries

Only `echo` and the RAG stub exist. No shell, file, web or code-execution tools; no
parallel or streaming tool execution.
