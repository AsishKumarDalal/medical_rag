# H3 — Context budget and compression

**Status:** complete (`f7a1a25`)

## What was built

- `harness/context.py` — per-message token estimates, a request budget that reserves
  completion tokens, and `ContextManager.apply()` with two deterministic passes:
  - **45%:** replace older, long tool outputs (all but the newest two) with a short
    recoverable stub for the request only;
  - **75%:** summarize the middle into one message, never touching the first three
    or last six messages.
- Every pass is idempotent, records before/after token counts, and logs its events.
- If the summarizer fails, a deterministic truncation is used instead.

## Verification

```text
.venv/bin/python -m pytest test/test_context.py -q
17 passed
```

`test/docs/h3-context.md` records both passes: 20 messages / ~5,396 tokens became
~2,376 tokens after stubbing, and the compression pass reduced 20 messages to 11
while the first three and last six stayed byte-identical.

## Boundaries

Token counts use the documented 4-characters-≈-1-token estimate, not a provider
tokenizer. No embedding memory or cross-session compression.
